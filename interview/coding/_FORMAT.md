# Coding problem conventions (read fully)

Layout per tier (basic | advanced):
  <tier>/solution/NN_name.py   full reference implementation (you write this)
  <tier>/tests/test_NN_name.py tests (you write this)
  <tier>/blank/NN_name.py      GENERATED by ../make_blank.py from the solution — do NOT write by hand.

## solution/NN_name.py
- Module docstring = the interview prompt, written the way an interviewer states it in a shared editor:
  title, a 3-8 line problem statement, the function signatures to implement, constraints (shapes, allowed libs,
  numerical notes), a suggested time budget ("Interview budget: 25 min"), and 2-4 "Discussion follow-ups" the
  interviewer would ask after (complexity, stability, how it scales, where it's used in practice).
- Only numpy + torch (CPU) + stdlib. No other deps. Everything must run on CPU in < 20 s.
- Define `__implement__ = ["func_name", "ClassName.method_name", ...]`: the exact set of functions/methods the
  candidate must write. make_blank.py replaces those bodies with a TODO stub (`raise NotImplementedError`) while
  KEEPING the def line and docstring. Every listed callable MUST have a docstring that fully specifies inputs,
  outputs, shapes, and any edge cases — that docstring is all the candidate sees.
- Helpers that are given to the candidate (data generators, reference utilities, tiny models) are NOT listed in
  `__implement__` and remain intact in the blank.
- Deterministic: seed everything you generate (torch.manual_seed / np.random.default_rng(0)).

## tests/test_NN_name.py
- Must define `def run(mod):` where `mod` is the imported module (blank or solution). Use plain asserts with
  helpful messages; group into several named checks, e.g. `check_shapes(mod)`, `check_matches_reference(mod)`,
  `check_edge_cases(mod)`. `run` calls them in order and prints one line per passed check, e.g. `  ok  shapes`.
- Compare against torch/numpy references wherever one exists (e.g. torch.nn.functional.scaled_dot_product_attention,
  torch.optim.Adam, torch.nn.LayerNorm). Use tolerances appropriate to float32.
- Tests must NOT import from the solution module by name; they only use `mod`.
- Keep total test runtime < 20 s CPU.

## Difficulty targets
basic = classic ML algorithms / building blocks a strong candidate writes from memory in 15-25 min.
advanced = generative modeling / systems problems 25-45 min, with a provided scaffold so the interesting part is
what gets implemented (e.g. a tiny MLP is given, the candidate writes the flow-matching loss + sampler).
